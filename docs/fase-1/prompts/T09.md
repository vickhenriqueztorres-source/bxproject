## 1. Implementador

```yaml
task_id: T09
agent: backend-implementation-agent
objective: >
  Implementar POST /contracts com Idempotency-Key e reserva de stake via Wallet Adapter, as consultas do
  usuário e as rotas admin de usuários, contratos, índice e bloqueio, todas auditadas.
context:
  - ORCHESTRATOR.md §9.2 (abertura, estados, compensação) e §9.3 (movimentos do ledger)
  - skills/02-financial-invariants/SKILL.md (idempotência, reserva reserve:{contract_id})
  - skills/04-security-iam/SKILL.md e references/api-guide.md (matriz RBAC com as rotas admin novas)
  - skills/05-resilience-patterns/SKILL.md (saga/compensação)
  - skills/08-database-foundation/references/schema.md (contracts, outbox, audit_logs, indices)
  - contracts/openapi.yaml (T03), services/wallet-adapter (T04), services/tick-engine (T05)
skills: [01-project-context, 02-financial-invariants, 04-security-iam, 05-resilience-patterns, 08-database-foundation]
acceptance_criteria:
  - "Idempotência insert-first: UNIQUE (user_id, idempotency_key) + request_hash; mesma chave e mesmo corpo → mesma resposta; corpo diferente → 422"
  - "DTO estrito: symbol, direction UP|DOWN, stake_minor inteiro 100..10000; qualquer outro campo → 400"
  - "Preço de entrada = último tick oficial do Postgres; expires_at = ts do tick de entrada + 60 s"
  - "Contrato CREATED + outbox RESERVE_STAKE na mesma transação; OPEN só após a reserva confirmada; compensação conforme ORCHESTRATOR §9.2 (Compensação)"
  - "Índice PAUSED → 409 INDEX_PAUSED; usuário bloqueado → 403; rate limit de 30 POST /contracts por minuto por usuário"
  - "GET /contracts (só do sub, filtros result e status, paginação) e GET /contracts/{id} (de outro usuário → 404)"
  - "GET /indices/{symbol}; GET /admin/users (busca por e-mail, saldo do Blnk, via client api-admin); GET /admin/users/{id}/transactions; GET /admin/contracts (filtro status); GET /admin/audit-log"
  - "POST /admin/indices/{symbol}/pause|resume e POST /admin/users/{id}/block|unblock: ADMIN + MFA + motivo, gravam audit_logs; bloqueio por migration nova user_blocks e desabilita o usuário no Keycloak"
  - "Nenhuma rota altera saldo diretamente"
  - "Métricas contract_created_total, contract_open_total e latência de POST /contracts"
budget: { max_steps: 3, max_tokens: 400000, timeout: 120m }
```

Guardas específicas: checa a chave e depois grava (corrida); mesma chave com corpo diferente devolve
cache; preço de entrada vindo do cliente; reserva no Blnk fora da saga.
