## 1. Implementador

```yaml
task_id: T02
agent: backend-implementation-agent
objective: >
  Configurar o realm "indices" num Keycloak real, exportá-lo para infra/keycloak/realm-indices.json
  (importado no start) e criar o seed das contas de demonstração a partir do .env.
context:
  - skills/04-security-iam/SKILL.md (S-01 a S-03) e references/api-guide.md (matriz RBAC)
  - ORCHESTRATOR.md §9.7
  - docs/vendor/keycloak/
  - infra/compose.yaml (da T01)
  - docs/fase-1/08-versoes-fixadas.md ("Configuração da corrida": e-mails das contas seed)
skills: [01-project-context, 04-security-iam]
acceptance_criteria:
  - "Realm gerado configurando um Keycloak real (kcadm.sh ou Admin REST da doc anexada) e exportado; JSON nunca escrito à mão"
  - "Clients web e admin: públicos, Authorization Code + PKCE S256, sem implicit e sem direct access grants, redirect URIs e web origins exatos"
  - "Client confidencial api-admin só com view-users/manage-users, para listar e bloquear usuários (T09)"
  - "Audience mapper: o access token tem aud contendo api; roles em realm_access.roles"
  - "Roles USER, AUDITOR, ADMIN; USER é a role padrão no cadastro"
  - "Cadastro habilitado com verificação de e-mail via Mailpit"
  - "TOTP opcional para USER e obrigatório para ADMIN e AUDITOR"
  - "Brute force detection após 5 falhas; access token de 5 min; refresh token com rotação e reuso 0"
  - "Seed idempotente de admin, auditor e aluno com senhas lidas do .env"
budget: { max_steps: 3, max_tokens: 400000, timeout: 90m }
```

Guardas específicas: campos de realm inventados; variáveis de admin de versão antiga (use
`KC_BOOTSTRAP_ADMIN_*` se a doc anexada confirmar); sem audience mapper; roles no claim errado.
